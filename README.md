# TZ_BankAccount_REST_forPioner

# 🏦Система управления банковскими аккаунтами 💳

📝 Backend-приложение для управления банковскими аккаунтами с безопасным доступом и операциями.
Реализовано на Spring Boot с использованием современных технологий и подходов.

## Особенности:

3.	 пользователи создаются миграциями. Для обычных пользователей нет операции создания. Для тестов создаем напрямую в DAO.
4.	У пользователя может быть более одного PHONE_DATA (должен быть как минимум 1).
5.	У пользователя может быть более одного EMAIL_DATA (должен быть как минимум 1).
6.	У пользователя должен быть  строго один ACCOUNT.
7.	Начальный BALANCE в ACCOUNT указывается при создании пользователя.
8.	BALANCE в ACCOUNT не может уходить в минус ни при каких операциях.
9.	Валидация входных API данных.


## 🌟 Основная функциональность

- 1) Добавлено кэширование запросов getUserById
### Для зарегистрированных пользователей
- 2)CREATE (только для определенных внутри пользователя данных), UPDATE операции для пользователя. Пользователь может менять только собственные данные:
- - a) может удалить/сменить/добавить email если он не занят другим пользователям
- - b) может удалить/сменить/добавить phone если он не занят другим пользователям
- - c) остальное менять не может
-
- 3)READ операция для пользователей.  «Поиск пользователей» (искать может любой любого) с фильтрацией по полям ниже и пагинацией (size, page/offset):
- - a) Если передана «dateOfBirth», то фильтр записей, где «date_of_birth» больше чем переданный в запросе.
- - b) Если передан «phone», то фильтр по 100% сходству.
- - c) Если передан «name», то фильтр по like форматом ‘{text-from-request-param}%’
- - d) Если передан «email», то фильтр по 100% сходству.
-
- 4)Настроен планировщик - раз в 30 секунд BALANCE каждого клиента увеличиваются на 10% но не более 207% от начального депозита.
- - Например:
- - Было: 100, стало: 110.
- - Было: 110, стало:121.
-
- 5)Реализован функционал трансфер денег от одного пользователя к другому.
- - Вход: USER_ID (transfer from) – берет у авторизованного из Claim токена, USER_ID (transfer to) из запроса, VALUE (сумма перевода) из запроса.
- - Считаем эту Операцию «банковской» (высоко-значимой), реализовано со всеми нужными валидациями и потоко-защищенной.
-
- 6)Настроен swagger.
- 7)Реализовано значимое логгирование.

- 8)Покрыто unit тестами функционал трансфера денег
- 89)Интеграционный тест API операций с телефоном (добавление/редактирование/удаление) покрыто через testcontainers с использованием MockMvc.

## Запросы для тестирования в Postman

###  API для аутентификации/регистрации - без токена
- 
- Аутентификация пользователя - в ответе получим токен
- - POST: http://localhost:8080/api/auth
- - {
- -  "email": "79202278899",
- -  "password": "12345678"
- -  }
- -  в ответе придет токен, он нужен для остальных запросов

### API c пользователями

- Получить станицы со списком всех пользователей с фильтрами
- -GET: http://localhost:8080/api/users/filter
- - в Auth/Bearer Token вставить токен
-
- - Полный фильтр с пагинацией:
- - - GET http://localhost:8080/api/users/filter?name=maria&dateOfBirth=1985-12-15&phone=79204445566&email=mari@example.com&page=1&size=5
-

### API c операциями с телефоном, можно только управлять своими телефонами
- Добавление нового телефона
- - POST: http://localhost:8080/api/users/1/phones
- - {
- -    "number":"71151118321"
- - }
-
- Изменение существующего телефона
- - PUT: http://localhost:8080/api/users/2/phones
- - {
- -    "oldNumber":"71151118321",
- -    "newNumber":"71151118322"
- - }
-
- Удаление телефона
- - DELETE: http://localhost:8080/api/users/2/phones
- - {
- -    "number":"71151118322"
- - }
-

### API c операциями с email, можно только управлять своими email
- Добавление нового email
- - POST: http://localhost:8080/api/users/3/emails
- - {
- -    "email":"maria1@example.com"
- - }
-
- Изменение существующего email
- - PUT: http://localhost:8080/api/users/3/emails
- - {
- -    "oldEmail":"mari888@example.com",
- -    "newEmail":"mari@example.com"
- - }
-
- Удаление email
- - DELETE: http://localhost:8080/api/users/3/emails
- - {
- -    "email":"maria1@example.com"
- - }


- Сделать перевод с аккаунта на аккаунт другого пользователя
- - POST: http://localhost:8080/api/transfer
- - в Auth/Bearer Token вставить токен юзера
- - {
- -   "toUserId": 1,
- -   "amount":10.00
- -  }


##  Работа с API через Swagger

После запуска приложения:

1. Откройте в браузере:
   http://localhost:8080/swagger-ui/index.html

2. Авторизация:
- Нажмите Authorize в правом верхнем углу
- Вставить JWT-токен (полученный через запрос /api/auth)
- Если необходимо ввести другого пользователя, то:
  Authorize/ Logout вставить другой JWT-токен

#### API:
- API для аутентификации - доступен всем без авторизации
- API c операциями по добавлению, обновлению, удалению email. Пользователь может менять только собственными данными - доступен только авторизованным пользователям
- API c операциями по добавлению, обновлению, удалению телефона. Пользователь может менять только собственными данными - доступен только авторизованным пользователям
- API c операциями по переводам - доступен только авторизованным пользователям
- API c операциями по управлению пользователями

#### Дополнительно:
- Изменения структуры таблиц БД, которая описана в ТЗ:
- - в таблицу ACCOUNT добавлено поле  INITIAL_BALANCE DECIMAL(15, 2) - для выполнения условия - при увеличении баланса клиента, он не должен былть более 207% от начального депозита
- -  добавлена таблица TRANSACTION - для сохранения операции трансфера денег от одного пользователя к другому
